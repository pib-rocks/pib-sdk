## Goal
Extend `pib_sdk.features.camera.Camera` with depth functionality so own projects can:
- get a depth frame, and
- get the depth/distance at an (x, y) pixel of the current camera image,
calling the ROS2 services (over rosbridge) added in Scope 1.

## Scope-1 service contract (verified in pib-backend PR-1674-backend)
- `GetDepthFrame.srv` -> fields: int32 width, int32 height, string encoding, string depth_base64.
  encoding "16UC1"; depth_base64 is little-endian uint16 millimeters (numpy.frombuffer(..., uint16).reshape((height,width))); 0 = invalid.
- `GetDistanceAtPx.srv` request int32 x, int32 y -> response float32 distance_mm. 0.0 = missing cache/out-of-bounds/invalid.
- Services live on the camera ROS node (same rosbridge host/port as get_camera_image).

## Desired pib_sdk API (in src/pib_sdk/features/camera.py, class Camera)
- `get_depth_frame(timeout=10.0) -> numpy.ndarray | None` — call get_depth_frame service, decode depth_base64 -> uint16 (H,W) mm array (0 = invalid). Return None on no data/error.
- `get_distance_at_px(x: int, y: int, timeout=10.0) -> float` — call get_distance_at_px service; return distance_mm (float).
- Keep the existing snapshot API (get_snapshot_bytes / save_snapshot) and the Camera host/port/context-manager/close behaviour unchanged.
- Optional but helpful: helper `save_depth(path, ...)` if natural; and mention units (mm) in docstrings.
- Return numpy / OpenCV-friendly array (dtype uint16, shape (height,width)) for the depth frame.
