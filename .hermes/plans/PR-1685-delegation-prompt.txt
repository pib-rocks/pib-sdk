## Goal
Expose TIMED multi-waypoint trajectory playback in pib-sdk so programs can play pose sequences that
BLEND smoothly through the waypoints instead of stopping at each pose. This is the prerequisite for
PR-1161 (Blockly play movement sequence with smooth transitions).

## Backend contract (pib-backend develop, PR-1660 merged as f6c2609e — DO NOT modify pib-backend)
- `ros_packages/motors/pib_motors/pib_motors/trajectory_executor.py`: fixed-rate (100 Hz) software trajectory
  controller. Interpolates each joint over `time_from_start` via-points with monotone cubic Hermite (PCHIP),
  so motion blends THROUGH via-points instead of stopping.
- `motor_control.apply_joint_trajectory` uses the executor when `is_software_trajectory(jt)` is True, which is:
  * any message with a non-zero `time_from_start`, OR
  * more than one waypoint in the STANDARD JointTrajectory layout (each point carries a position per joint).
  Otherwise the legacy path (one point per motor, single position, positions[0]) is used -> stop-per-point.
- ROS interface: `datatypes/srv/ApplyJointTrajectory.srv` = request `trajectory_msgs/JointTrajectory joint_trajectory`
  -> response `bool successful`.
- Positions are in INTERNAL units (hundredths of a degree). See `features/poses.py` (`_INTERNAL_UNITS_PER_DEGREE`).

    "time_from_start":{"sec":0,"nanosec":1_000_000}}`  # hardcoded 1 ms.
